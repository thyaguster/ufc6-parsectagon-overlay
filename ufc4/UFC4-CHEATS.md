# UFC 4 cheat integration

## Verified local port interface

PORTHEON's UFC 4 port reads `%LOCALAPPDATA%\UFC4Native\cheats.json` during its game-image link step. Its bundled `ufc4-cheats.json` defines `ufc4_stamina_left` and `ufc4_stamina_right`, but those startup selections do not meet the overlay's live-cheat requirement. The UFC 4 menu no longer writes this file. The local config remains with an empty `enabled` list.

On the local v28 prepared game image, the stamina hook pattern has exactly one match at guest offset `0x698113`. An offline call to PORTHEON's own cheat linker applied the left, right, and combined blocks with no skipped hooks. Two runtime hook variants caused fight-start guest faults at offsets `0x69811b`–`0x69811d` even when Off. Those addresses are **8–10 bytes after the hook start**, inside the 15-byte absolute jump we had installed. The game enters the instruction at byte 8 independently. PORTHEON's own hook replaces only the first 8 bytes; the runtime absolute jump overwrote a valid entry point. Both runtime variants have been removed from the production build.

The working stamina bridge follows PORTHEON's link-time eight-byte hook and adds a separate writable four-byte mask with marker `UFC4LIVE_STAMINA1`. The hook starts with mask `0` (normal stamina). The overlay scans for the marker in a writable page and changes only the mask during the fight. It does not patch running executable code or write PORTHEON's `cheats.json`. The wrapper in `port_bridge/cheats.py` calls the port's original cheat linker for its existing packs, then appends the dormant hook and data page. The original script is backed up as `scripts/cheats_portheon.py` in the local PORTHEON install.

The port also bundles an experimental damage pack for head, body, and legs of the left fighter. Its v28 adaptation had never been tested in a fight. A local live-control prototype linked its eight-byte hook and all eight head/body/leg combinations successfully, but the user confirmed that the head toggle did not stop damage. A diagnostic hook counted 88,268 calls with head protection On and **zero** calls passing the pack's first condition, `r8 == 4`; its last sampled value was `0x7ffffffffffffffc`. The pack's v28 condition is incompatible with the tested fight. The damage submenu and bridge were removed from the working build. Finding a verified v28 health path is required before adding a live no-damage control. No bundled career money or skill-point cheat was found. UFC 6's memory addresses and hooks cannot be reused in UFC 4's native port.

The public [GoldHEN CUSA14204 17.00 trainer](https://github.com/GoldHEN/GoldHEN_Cheat_Repository/blob/main/shn/CUSA14204_17.00.shn) contains the same damage-hook logic PORTHEON adapted. It is not a separate v28 implementation. A search of public trainer source found no verified v28 no-damage patch. A second read-only v28 probe tested the proposed unified-health approach after confirmed head/body hits: the generic accessor ran 634,888 times, but its expected `rax == 4` health index occurred zero times. A sampled `100.0` value belonged to an unrelated game setting. Do not turn that accessor into a damage-blocking hook without identifying the actual health write. The diagnostic wrapper is temporary; the production bridge remains stamina-only.

The local save contains `PROFILE` and `EXTRADATA0` data/index pairs. A read-only header and keyword check found career-related strings in `PROFILE`, but no identified money or skill-point field. That is insufficient to edit a save safely. Career values need a controlled before/after save comparison and a backup before a write path is considered.

## Test status

- The former startup-config helper and UI were removed after the user clarified the live-cheat requirement.
- The stamina hook/link test used the installed v28 game's prepared image without writing to the game or saves.
- Both runtime hook variants failed their in-game fight-start test with the cheat Off; the safe focus-mute build restored normal fights and passed the Windows-key audio check.
- The launch-time bridge was tested offline against a synthetic image and the actual prepared UFC 4 image. The eight-byte patch preserves the instruction at byte 8, its code reads the separate writable mask, and its extra segments have read/execute and read/write flags respectively. The overlay's marker discovery and mask changes pass a synthetic writable-page test.
- The bridge and its core passed staged in-game checks: a fight starts normally, opening Cheats with both options Off leaves the fight stable, and the left, right, and combined stamina controls work immediately during a fight without a crash. The local PORTHEON startup cheat selection remains empty; the pre-reset config and safe core are backed up in the ignored build folder.
- The damage pack's head, body, and leg blocks each link on the local v28 prepared image. The live prototype preserved the instruction after the eight-byte hook and ran fights safely with the options Off. Turning On no head damage changed its writable mask but did not protect health. A diagnostic probe confirmed that the pack's `r8 == 4` gate never passed in the tested fight. The verified stamina-only wrapper and core were restored in the local game. The damage prototype and probe are retained only under ignored `ufc4/.build` files for further investigation.
